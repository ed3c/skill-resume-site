01

Overview總覽

Drop-in remote engineering for the difficult part. 加入既有團隊，處理最困難的一段。

My work connects mobile systems, full-stack delivery, and software agents. I enter an existing codebase, define one bounded result, ship a reviewable pull request, and leave executable knowledge behind. 我的工作把行動系統、全端交付與軟體 Agent 連在一起。我加入既有 Codebase，先定義一個清楚成果，再交付可審查的 Pull Request，並留下可執行的團隊知識。

The portfolio is designed for two kinds of work. The first is a remote role in an Agent, AI, or platform team. The second is a part-time studio engagement where a company needs a senior engineer for a specific integration, automation, or reliability problem. 這份履歷對應兩種合作。第一種是 Agent、AI 或平台團隊的全遠端職位。第二種是個人工作室模式：公司針對一個整合、自動化或可靠度問題，短期加入一位資深工程師。

The work is not limited to producing prompts or demos. A result includes code, tests, a working demonstration, an architecture note, known risks, and a clear next decision. 工作不只產生提示詞或 Demo。完整成果包含程式碼、測試、可操作展示、架構說明、已知風險，以及下一個決策。

02

Why now

Code generation is abundant. Reliable execution is not. 程式碼生成已普及，可靠執行仍然稀缺。

The useful layer now sits around the model: clear task boundaries, reusable Skills, controlled tool access, durable state, automated checks, and proof that the work actually finished. 現在真正有價值的部分位於模型周圍：清楚的任務邊界、可重用 Skills、受控工具權限、可恢復狀態、自動檢查，以及工作確實完成的證明。

01

First-hand finding第一手發現

Many agent failures are not caused by a weak model. They come from missing contracts, unclear stop conditions, fragile tool calls, and work that was never verified.許多 Agent 失敗不是模型不夠強，而是缺少契約、停止條件不清楚、工具呼叫脆弱，或工作從未真正驗證。

02

What becomes hard to copy什麼會逐漸難以複製

The lasting asset is a growing library of executable procedures, test oracles, evidence contracts, domain adapters, failure cases, and recovery rules.長期資產是持續累積的可執行程序、測試判定器、證據契約、領域 Adapter、失敗案例與恢復規則。

03

Proof over presentation證據優先於包裝

A working demo matters, but the stronger signal is the path behind it: scoped change, test output, reviewable diff, accepted result, and a record another engineer can replay.可運作 Demo 很重要，但更強的訊號是背後的路徑：受控改動、測試輸出、可審查 Diff、已驗收結果，以及其他工程師可以重跑的紀錄。

The career thesis is simple: model capability will keep improving, so the durable advantage is the system that turns capability into safe, repeatable delivery.職涯命題很直接：模型能力會持續進步，因此更耐久的優勢，是把模型能力轉成安全、可重複交付的系統。

06

Loop engineering迴圈工程

Turn model output into shipped evidence. 把模型輸出轉成可交付證據。

An LLM can suggest a good answer. Software delivery needs a stronger rule: execute the result, inspect deterministic failures, repair the exact condition, and repeat until the agreed checks pass.LLM 可以提出好答案，但軟體交付需要更強的規則：執行結果、讀取確定性失敗、修正精確條件，再重跑到約定檢查通過。

General evaluator pattern一般評估迴圈

Generate → Evaluate → Feedback → Revise

A generator produces a candidate. An evaluator reviews quality and sends feedback. This works well when quality can be described but cannot be fully checked by code.Generator 產生候選結果，Evaluator 評估品質並回傳意見。這適合品質可以描述，但無法完全用程式檢查的工作。

Delivery specialization軟體交付版本

Spec → Change → Execute → Assert → Repair

The evaluator is primarily a parser, test, type checker, schema, or policy gate. An LLM review can assist, but it cannot create release truth.Evaluator 主要是 Parser、Test、Type Checker、Schema 或 Policy Gate。LLM 評語可以協助，但不能建立 Release Truth。

STE100-inspired

Controlled specifications for Agentic work用受控規格降低 Agentic 工作歧義

The method borrows controlled-language principles: one action per step, explicit nouns, short procedural sentences, and machine-verifiable outputs. It is an engineering adaptation, not an official ASD-STE100 conformance claim.這套方法借用受控語言原則：每一步只有一個動作、明確寫出名詞、程序句保持短小，輸出必須能由機器驗證。這是工程應用，不是官方 ASD-STE100 合規聲明。

  1. 01

    Define one measurable outcome.定義一個可衡量成果。Name the observable result before choosing tools.先說清可觀察結果，再選工具。

  2. 02

    Name exact inputs and outputs.寫清楚輸入與輸出。Do not hide dependencies behind vague words.不要用模糊詞隱藏相依條件。

  3. 03

    Split one action into each task.每個 Task 只放一個動作。Keep branching logic visible.讓分支邏輯保持可見。

  4. 04

    Execute the smallest reviewable change.執行最小可審查變更。Reduce blast radius and review time.縮小影響範圍與審查時間。

  5. 05

    Run deterministic assertions.執行確定性斷言。Prefer tests, schemas, parsers, and policy checks.優先使用測試、Schema、Parser 與 Policy Check。

  6. 06

    Repair the exact failed condition.修正精確失敗條件。Use stderr and evidence instead of broad rewrites.依 stderr 與證據修正，不做大範圍重寫。

  7. 07

    Publish the result and evidence.發布成果與證據。Leave a path another engineer can replay.留下其他工程師可以重跑的路徑。
